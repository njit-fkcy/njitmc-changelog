### B. 官网登录改造（MUA 皮肤站 OAuth）

| # | 操作 | 结果 / 证据 |
|---|---|---|
| B1 | 定位问题：`/api/launcher/login/complete` 报「MUA 身份校验失败」 | 实测 MUA 已关闭 `yggdrasil/authserver/validate`（恒 400）与 `yggdrasil/sessionserver/.../profile`（返回 79 字节反爬文本），union 路径 `/api/union/yggdrasil/.../profile` 仍 204 |
| B2 | 与 MUA 沟通后选 **MUA 皮肤站 OAuth**（非 Union OAuth） | 两站各建 OAuth2 应用：client 41（主站）、42（测试站），回调 `/api/mua/oauth/callback` |
| B3 | 探测端点：`/oauth/authorize`、`/oauth/token`、`/api/user`（Bearer + `Accept: application/json`） | authorize 未登录 302 → `/auth/login`；token 错误凭据 401 `invalid_client`；user 无 token 401 `Unauthenticated` |
| B4 | 后端新增 `GET /api/mua/oauth/start` 与 `GET /api/mua/oauth/callback`；配置 `mua_oauth.json`（600） | start 302 且参数正确；伪造 state → `/#sso-error?reason=state` |
| B5 | 前端登录弹窗改「使用 MUA 账号登录 →」，旧表单与启动器按钮先设 `hidden` | 浏览器实测两站均生效 |
| B6 | 首次真实登录失败：`reason=token:invalid_client` | 截图 secret 只有 37/36 位（应为 40 位），改文本 secret 后通过 |
| B7 | 第二次真实登录失败：`reason=user` | 日志显示 MUA 返回 `{'uid': 8697, 'nickname': 'xwan58401', ...}`，代码只认 `id`；改为 `body.get('id') or body.get('uid')` |
| B8 | **删除**旧登录代码（本步） | 见下节 |
| B9 | 回归验证 | 两站 `active`、首页 200、`oauth/start` 302、`session` 正常、4 个旧接口全部 **404**、`logout` 200、`/api/launcher/servers` 200 |
| B10 | **回归缺陷：点「使用 MUA 账号登录」无反应** | 原因：删除 `startLauncherLogin` / `finishLauncherLogin` 时按区间删除（`let launcherLoginPending…` 到 `function loginDialog(`），而 `startMuaOauth()` 与 `ssoFinish()` 恰好位于这段区间内，被一并删掉。`node --check` 只查语法，函数缺失不报错，所以未被发现。修复：在 `function loginDialog(` 前重新插入这两个函数（含 `token:invalid_client` / `invalid_grant` / `invalid_request` 提示映射）。验证：线上 `curl app.js` 含 `function startMuaOauth` 与 `function ssoFinish`，`node --check` 通过。**教训**：删除压缩 JS 的区间前，先确认区间内没有其它在用函数；改完必须做一次真实点击回归，不能只看语法检查 |

## 三、B8「删除旧登录代码」具体删了什么

### 服务端 `app.py`（两站，`/opt/blockdimension{,-test}/app.py`）

删除（备份 `app.py.bak-20261029-remove-legacy`）：

| 对象 | 说明 |
|---|---|
| `MUA_AUTH_URL` | 只被密码登录使用 |
| `LEGACY_MUA_PASSWORD_LOGIN` / `LEGACY_LAUNCHER_TOKEN_LOGIN` | 停用开关，已无引用 |
| `_authenticate_mua()` | 用账号密码换 token 的实现 |
| `POST /api/mua/login` | 网页密码登录接口 |
| `LAUNCHER_LOGIN_TTL` / `LAUNCHER_CODE_TTL` / `MUA_VALIDATE_URL` / `MUA_PROFILE_URL` / `_launcher_states` / `_launcher_codes` / `_launcher_auth_lock` / `_launcher_auth_gc()` / `_verify_mua_token()` | 启动器授权登录配套 |
| `POST /api/launcher/login/start` `/complete` `/exchange` | 启动器授权三个接口 |

保留：`MUA_COOKIE`、`_mua_sessions`、`_create_mua_session()`、`_mua_request_allowed()`（logout 仍在用）、`_NoMuaRedirect`（OAuth 仍在用）、`/api/mua/session`、`/api/mua/logout`。

### 前端 `app.js`（两站，`modern-public-20261008-01/app.js`）

删除（备份 `app.js.bak-20261029-remove-legacy`）：

- 登录弹窗里的密码表单 `<form id="mua-form">…</form>`（含用户名/密码输入、显示按钮、提交按钮）
- 「或者」分隔线、「用启动器授权登录」按钮与其说明
- `login(form)`（密码登录提交）
- `startLauncherLogin()` / `finishLauncherLogin()` 及其状态变量 `launcherLoginPending` / `launcherLoginRunning`
- `route()` 里的 `launcherlogin` 分支
- 点击委托里的 `launcher-login`、`dismiss-launcher-error`、`mua-toggle`
- `submit` 监听里针对 `mua-form` 的分支
- 资源岛顶部「启动器授权没有完成」提示条
- 资源岛卡片、资源列表、资源详情三处「用启动器登录」按钮（共 3 个）
- 启动器介绍页「官网一键授权」文案改为指向 MUA 登录

保留：`startMuaOauth()`、`ssoFinish()`、`route()` 的 `sso-ok` / `sso-error` 分支、账号弹窗与退出登录。
