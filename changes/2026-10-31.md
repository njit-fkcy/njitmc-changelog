# 2026-10-31 发布概括（启动器 1.5.5）

> 按项目规则 §九「变更日志与推送纪律」：推送完成后写概括并归档过程细节。本次排查过程见 `docs/变更日志-2026-10-30.md` 附录。

## 一、改了什么

**问题**：官网错误报告显示，1.20.1 整合包玩家被启动器自动选中了 Java 25（Mojang 官方启动器自带的 `java-runtime-epsilon`），叠加 Java≥24 自动追加的 `-XX:+UseCompactObjectHeaders` 后，Quark 4.0-462 / Zeta 1.0-31 在加载阶段崩溃：

```
-- MOD quark --
Failure message: Quark (quark) has failed to load correctly
java.lang.ArrayIndexOutOfBoundsException: Index 256 out of bounds for length 129
    at it.unimi.dsi.fastutil.objects.Object2ObjectOpenHashMap.rehash
    at org.violetmoon.zetaimplforge.event.ForgeZetaEventBus.subscribeMethod
```

**根因**：启动器 `ModJava.vb` 的 Forge Java 上限只覆盖到 `47.4.8`（与上游 PCL 当前 main 一致），而整合包用的是 Forge `47.4.10`，不在区间内 → Java 范围变成 `[17.0, +∞)` → 选中 Java 25。日志原文：`[ModJava] 自动选择以下范围的 Java：[17.0, +∞)` → `已选定 Java：Java 25`。

另有一条 Java 17 的崩溃：整合包内 `tablist-1.0.2.jar` 的 class 版本为 65（Java 21 编译），使用 Java 17 必崩。故该整合包唯一可用 Java 为 **21**。

**客户端（1.5.5 / 443，快照 444）**：
1. `ModJava.vb`：Forge 上界 `47.4.8` → `47.99.99`，1.20.1 恢复「最高 Java 21」。
2. `ModPackRevision.vb`：`WriteMark` 增加 `JavaVersion` 参数，只在服务端声明时写入实例 `PCL\njitmcl-pack.json`；首装、补丁更新、仅同步哈希三处透传；`FindPackInstances` 会给没有该字段的老标记补写。
3. `ModJava.GetJavaRequirement`：读取实例标记里的 `javaVersion`，有则锁定 `[N, N+1)`；**没有该字段的整合包完全按原有自动选择**。
4. `PageLaunchRight.xaml.vb`：首次安装写标记时带上 `javaVersion`。

**服务端**：
- `app.py` 的 `_launcher_pack_view` 与管理端 `cleaned` 增加 `javaVersion`（int 安全转换），管理页保存不会丢字段。
- 中控 `changzhu-1.0.0` 写入 `javaVersion: 21`（revision 仍为 16）。

**效果**：玩家有 Java 21 → 直接用；只有 Java 17 → 范围 `[21,22)` 无解 → 启动器自动从 Mojang 下载 Java 21，失败则弹窗提示；其他整合包不受影响。

## 四、回滚方式

- 客户端：两处运行目录用 `.bak-20261031` 覆盖；源码回退 `ModJava.vb` / `ModPackRevision.vb` / `PageLaunchRight.xaml.vb` 的 Java 约束改动后按更高版本号重编译（`versionCode` 不可回退）。
- 分发：恢复 `njitmcl.json.bak-20261031` 与两站 `app.js.bak-20261031`；删除内网 `_launcher/v1.5.5/`；GitHub 删除 Release `v1.5.5`。
- 服务端：覆盖 `app.py.bak-20261031-javaver` 与 `website.sqlite3.bak-20261031-javaver` 后 `systemctl restart blockdimension`。

## 五、遗留事项

- 整合包内 `tablist-1.0.2.jar` 要求 Java 21；若有玩家机器上只有 Java 17 且自动下载失败，仍会收到「需要 Java 21」提示。是否移除该模组需另行决定（移除要走整合包补丁流程）。
- `gh.llkk.cc` 当前 522，仅作为第五后备源。

## 六、发布工具 1.0.1（同日）

**改动**

1. `pack_edit.read_pack_meta()`：从原始包自动读名称、版本、加载器、加载器版本与 MC 版本。mrpack 读 `modrinth.index.json`，CurseForge 读 `manifest.json`，离线包只识别格式。

3. 存档包：自动用压缩包第一层目录名填存档名称与标识。
4. 提交中控的整合包数据新增 `javaVersion`（0 = 不指定）与 `enabled`。
5. 修正整合包主流程把包推到启动器仓库（`githubRepoLauncher`）的问题，改为 `githubRepo`（`PCL-NJITMCL-Modpacks`）。
