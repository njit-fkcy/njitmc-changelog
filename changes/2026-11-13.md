## 五、活动签到（启动器 + 网站双端）

### 5.1 需求

管理员在后台对**已截止报名**的活动开启签到，填写签到截止时间；6 位签到码在现场公开。成员在启动器或网站上看到自己报名的活动高亮「正在签到」，点签到输入 6 位码即可；后端按登录身份匹配本人报名记录，完成签到。

### 5.2 数据层（`club_store.py`）

| 项 | 内容 |
| --- | --- |
| 新增列 | `events.checkin_deadline INTEGER NOT NULL DEFAULT 0`（旧库自动 `ALTER TABLE`） |
| `checkin_open(row)` | 已开启 + 报名已截止（`now >= ends_at`）+ 未到签到截止 + 未结算；`deadline=0` 视为不限时（兼容历史已开启数据） |
| `set_checkin(id, enabled, deadline, reset_code)` | 关闭清空截止时间；开启要求 `now >= ends_at` 且 `deadline > now`，码为空或 `resetCode` 时重新生成 |
| `checkin(event_id, student_no, code)` | 匿名签到（现场输学号），保留原行为 |
| `checkin_by_account(event_id, account_id, code)` | 登录态签到：学号取自信息模板（缺学号返回 428），先按账号匹配报名记录，找不到再按学号唯一匹配 |
| `create_event` / `update_event` | 不再接受签到开关，编辑活动不会误关正在进行的签到 |
| `my_events` | 新增 `checkinOpen` / `checkinDeadline`，仅在「已报名且未签到」时为真 |

### 5.3 接口

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| PUT | `/api/manage/club/events/<id>/checkin` | 管理员会话 + CSRF | `{enabled, deadline, resetCode}`；报名未截止或已结算时拒绝开启 |
| POST | `/api/club/events/<id>/checkin` | 网站会话 + CSRF | `{code}`，按会话账号签到本人报名记录 |
| POST | `/api/launcher/club/events/<id>/checkin` | 设备令牌 | `{code}`，启动器按授权身份签到 |
| POST | `/api/club/checkin` | 无（保留） | 原匿名接口（学号 + 码），供现场人工协助 |

### 5.4 两端界面

- **网站**：活动列表卡片与「个人中心 → 活动记录」在签到窗口内高亮并显示「立即签到」；活动详情显示签到截止时间与入口；弹窗输入 6 位码（仅数字，回车提交）。管理端活动行新增「签到」按钮，面板内可设截止时间、查看/复制/重新生成签到码、关闭签到；活动编辑器移除原签到复选框。
- **启动器**：活动卡片高亮（蓝色边框）并显示「立即签到」；活动详情与「个人中心 → 活动记录」同样提供入口；点击弹出面板内签到浮层（6 位数字输入 + 确认），失败原因就地显示。
